# Contributing

Install a supported Python and uv, then run `uv sync --locked`. Run `uv run python scripts/verify.py` before proposing a change. Tests use isolated temporary databases and synthetic content. Record the failing case when fixing a bug and check both transports for changes to tool contracts.

Catalog contributions need original or appropriately licensed content, a clear conceptual mapping, its limitation, confirmed familiarity requirements, progress/spoiler boundaries and a transfer question. Cite factual claims about existing works. Keep interest separate from knowledge and self-report separate from verification.

For evaluation changes, version the cases, preregistration and manifest, and report changed assumptions. Preserve negative results. Keep the test split out of tuning. New dependencies need justification and a license/advisory check. Use existing domain logic through public entry points.

The project uses MIT for original code, documentation and bundled fixtures. Submit only material you have the right to contribute under that license, preserve required third-party attribution and describe AI assistance accurately. All fixture students and pilot records are artificial. Start with a reproducible issue or a small pull request; report security findings through SECURITY.md's private channel.
