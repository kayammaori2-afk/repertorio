# Repertorio v0.2.0 — first use and study preparation

Scope: improve the existing assistant-native experience and prepare stronger evaluation and an adult pilot. No own interface, hosted service, automatic recruitment or claimed learning improvement. The v0.1 ranking weights, catalog, labels, selector benchmark and artificial learning analysis remain frozen.

## Experience decisions

The first useful result is choosing a supported lesson and receiving suitable context or direct teaching. The old flow exposed internal IDs and required manual path editing. `setup` now generates JSON/TOML snippets with the running interpreter and chosen absolute database path. It refuses an existing output directory and never changes host settings, creates a database or grants deletion. Merge existing host settings rather than replacing them.

`learning_options` provides four topics with Portuguese/English labels, exact aliases, eligibility and missing requirements. It omits excluded experiences, does not echo user titles and never writes learner records. The assistant can ask one focused question or teach directly. Catalog requirements must never become learner facts without confirmation. Corrections retain revision/idempotency protections. Original tools remain compatible; the tenth tool is additive. Visual motion is inapplicable because the product remains inside another assistant.

Unsupported/ambiguous prose returns an unsupported discovery state. The MCP boundary resolves known aliases; the frozen selector retains canonical IDs. Arbitrary films/books and general semantic topic resolution remain unsupported.

Actual host inspection found a first-use failure: the assistant saved familiarity but omitted experience status, leaving the record ineligible. The guidance now explicitly exposes status and explains how an already-performed everyday experience maps to `completed`, only when stated by the learner. The failed trace and corrected fresh-profile run are both retained. A separate path test exposed JSON surrogate escapes invalid in TOML for emoji paths; UTF-8 TOML snippets now round-trip those paths.

## Research deliverables

- `experiment prepare/freeze/blind/analyze`: five-arm comparison including profile-plus-prompt, separate rater/operator files, two-rater checks, paired/grouped descriptions and explicit failures. [Protocol](tutor-evaluation.md).
- `study init/check/freeze/analyze-usability`: empty participant forms, separate answers and full learning protocol, consent draft, task/scoring/flow templates, readiness checks and missingness-aware counts. No human rows generated.
- Six adult usability sessions precede the existing 36-adult learning feasibility proposal. Targets/cutoffs are author choices, not power calculations. [Operational guide](../src/repertorio/data/study-guide.pt-BR.md).

`study check` exits 3 while reviews/fields remain pending. Freezing records local hashes and declarations, not authenticated consent, ethics approval, reviewer independence or complete enrollment. Published test questions can have prior-exposure contamination; the guide discloses this.

## Validation and status

Independent same-family static review identified integrity defects subsequently addressed with regressions: reconstruct blind mappings/provenance/failures; verify the actual rater packet; freeze the rubric before collection; reject blank consent; refuse final symlink destinations; serialize credential creation/revocation; accept a complete supported response collection. Catalog discovery now excludes candidates outside the selector's evaluated cap. Local declarations/hashes still cannot authenticate consent, ratings or a wholly replaced archive.

See `evidence/v0.2/` and [verification](verification.md) for executed checks. Artificial fixtures are not participants; host tests are technical interaction evidence. The pilot's empty CSVs and blocked readiness are expected. No recruitment, external expert review or learning outcomes occurred.

The public stable release remains v0.1.0 until a separate publication decision. This candidate is prepared in a feature branch; publication status is distinct from local validation.
